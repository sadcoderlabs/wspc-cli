# Version file generation helper refactor 設計

## 來源

這份 spec 對應 WSPC todo `tod_01KVND97JEQQHP2CATRJY68QYA`：`Share version file generation between scripts`。

Todo 內容把目標定義成一個 Ponytail shrink：`scripts/sync-spec.ts` 與 `scripts/build-version.ts` 目前各自計算 `SPEC_SHA`、組出 `src/version.ts` 內容、建立 `src/` 目錄並寫檔。這次要把重複的版本檔產生邏輯收進一個很小的 scripts 內部 helper，讓未來版本 metadata 格式只需要改一處。

## 目前狀態

`DEVELOPER.md` 定義了兩個相關 script 的責任：

- `scripts/sync-spec.ts` 從 `https://api.wspc.ai/openapi.json` 下載 live OpenAPI，寫入 `spec/openapi.json`，並同步產生 `src/version.ts`。
- `scripts/build-version.ts` 從本機 committed `spec/openapi.json` 產生 gitignored 的 `src/version.ts`，供 fresh clone、CI 與 install lifecycle 使用；沒有本機 spec 時寫入 stub `SPEC_SHA = "00000000"`。

`src/version.ts` 仍是 generated 且 gitignored，不應 commit。`npm run prepare` 會跑 `build-version`，`npm run sync-spec` 會覆寫同一個版本檔。這些 lifecycle 與 console output 都不是本次 refactor 要改的行為。

目前重複點很小但真實存在：

- 兩個 script 都用 `sha256` 取前八碼作為 `SPEC_SHA`。
- 兩個 script 都用相同 export 順序產生 `VERSION`、`SPEC_SHA`、`SPEC_FETCHED_AT`、`API_BASE`。
- 兩個 script 都負責建立 `src/` 目錄並寫入 `src/version.ts`。

## 目標

完成後，版本檔 body、sha prefix 與寫入路徑只由一個 helper 維護。`sync-spec` 和 `build-version` 仍保留各自的 orchestration：前者負責 fetch live spec 與寫入 `spec/openapi.json`，後者負責讀本機 package/spec 與處理 first-clone stub。

成功標準是：

- `SPEC_SHA` 計算集中到共享 helper。
- `src/version.ts` body 組裝集中到共享 helper。
- 寫入 `<rootDir>/src/version.ts` 與建立目錄的流程集中到共享 helper。
- `sync-spec` 與 `build-version` 的 observable output 不變。
- `src/version.ts` 仍然不進 git。

## 不在範圍內

這不是 release pipeline rewrite。不要在這次改動中：

- 改 `npm run prepare`、`npm run sync-spec`、`prepublishOnly`。
- 改 `spec/openapi.json` sync 行為。
- 改 `src/version.ts` export 名稱、順序或 timestamp 格式。
- 改 `sync-spec` 的 network error 訊息或 `build-version` 的 stub 行為。
- 新增 dependency、class、factory 或全 repo version metadata abstraction。
- 修改 `src/generated/`。

## 設計

新增一個 scripts 內部 helper，例如 `scripts/version-file.ts`。它只處理版本檔的純資料轉換與寫入，不知道 network、不知道 package 讀取，也不負責讀 OpenAPI 檔案。

建議 API 保持小：

```ts
export const STUB_SPEC_SHA = "00000000"

export function specShaPrefix(specBody: string): string

export function versionFileBody(args: {
  generatedBy: string
  packageVersion: string
  specSha: string
  fetchedAt: Date
  apiBase: string
}): string

export async function writeVersionFile(rootDir: string, args: Parameters<typeof versionFileBody>[0]): Promise<void>
```

`generatedBy` 保留目前第一行註解的 script 來源，例如 `scripts/sync-spec.ts` 或 `scripts/build-version.ts`：

```ts
// AUTO-GENERATED by scripts/sync-spec.ts — DO NOT EDIT
```

這樣兩個 script 的輸出仍能說明由誰產生，但 body 格式只在 helper 裡定義一次。

`sync-spec.ts` 的 responsibility 會變成：

1. fetch OpenAPI body。
2. 寫入 `spec/openapi.json`。
3. 用 `specShaPrefix(body)` 算 sha。
4. 從 URL 推導 `apiBase`。
5. 呼叫 `writeVersionFile(opts.rootDir, { generatedBy: "scripts/sync-spec.ts", packageVersion, specSha, fetchedAt: now(), apiBase })`。

`build-version.ts` 的 responsibility 會變成：

1. 讀 `package.json`。
2. 嘗試讀本機 `spec/openapi.json`。
3. 成功時用 `specShaPrefix(spec)`；缺檔時用 `STUB_SPEC_SHA` 並回傳 `stubbed: true`。
4. 呼叫同一個 `writeVersionFile()`，`generatedBy` 使用 `scripts/build-version.ts`。

不要把 `DEFAULT_URL`、`DEFAULT_API_BASE` 或 package 讀取塞進 helper。那些是兩個 script 各自的 orchestration 設定，留在原檔比較清楚。

## 測試策略

遵守 TDD，但不要為了這個小 refactor 加一整套 fixture。最小測試分三層：

1. 新增或更新一個極小 helper test，鎖住 `specShaPrefix()` 與 `versionFileBody()` 的 exact output。這個測試先寫會 fail，因為 helper 尚未存在。
2. 保留 `test/sync-spec.test.ts`，確認 `syncSpec()` 仍會寫 `spec/openapi.json` 與 `src/version.ts`，且 API base 仍從 fetch URL origin 取得。
3. 保留 `test/build-version.test.ts`，確認 local spec 產生 real sha，缺 spec 產生 stub sha。

建議驗證指令：

```bash
npm test -- test/version-file.test.ts test/sync-spec.test.ts test/build-version.test.ts
npm run typecheck
git diff --check
```

若實作者決定不新增獨立 helper test，至少要讓現有兩個 script tests 對 `src/version.ts` body 的關鍵欄位維持完整斷言；不要只驗證檔案存在。

## Grill-me review 結論

狀態：ready。

已鎖定決策：

- 這是 scripts 內部 shrink，不是 release behavior change。
- Helper 只管 sha、body 與寫檔；fetch、package 讀取、stub decision 仍留在呼叫端。
- 不新增 dependency 或跨 repo abstraction。
- `src/version.ts` 仍是 generated/gitignored，不能 commit。
- OpenAPI generated output 與 CLI generated commands 不在範圍內。

剩餘風險很低：主要是 `sync-spec` 與 `build-version` 的 generated header 目前不同，helper 必須保留 `generatedBy` 參數，避免把來源註解意外統一成錯的 script 名稱。
